# Core Vault 密码学协议与格式规范 (Protocol Specifications)

Core Vault 9.0.1 具备业内领先的多协议向下兼容引擎，能够无缝识别并解密所有历史版本格式。

---

## 📑 协议魔数与格式速查表 (Protocol Matrix)

| 协议版本 | 魔数标识 (Magic) | 对称算法 | 密钥派生算法 (KDF) | 适用场景 / 历史归属 |
| :--- | :--- | :--- | :--- | :--- |
| **V0** | 无魔数 (RAW) | AES-256-GCM | PBKDF2-HMAC-SHA256 (600,000 次) | 历史 0.0.1 遗留协议 |
| **V1** | `SAES\x02` | AES-256-GCM | Scrypt ($N=2^{14}, r=8, p=1$) | 历史 1.0.1 协议 |
| **V2** | `SAES\x03` | AES-256-GCM | Scrypt ($N=2^{17}, r=8, p=1$) | 历史 2.0.2 协议 |
| **V3** | `SAES\x04` | AES-256-GCM | Scrypt ($N=2^{18}, r=8, p=1$) | 7.0.2 / 8.0 默认高强度标准 |
| **V4** | `SAES\x05` | AES-256-GCM | Scrypt ($N=2^{18}$) + HKDF-SHA256 | 9.0.1 极速多任务独立派生标准 |
| **ChaCha20** | `SACH\x01` | ChaCha20-Poly1305 | Scrypt ($N=2^{18}$) + HKDF-SHA256 | 无 AES 硬件加速 CPU 节能优化 |
| **SFK V1** | `SFK\x01\x00` | AES-256-GCM | Scrypt ($N=2^{14}$) + HKDF-SHA256 | 纯文件锁模式 (支持主私钥后门救援) |
| **ECC V1** | `SAECC` | AES-256-GCM | X25519 ECDH + HKDF-SHA256 | 非对称公私钥加密 |
| **SAHW V1** | `SAHW\x01` | 外层物理硬件锁安全容器 | 卷序列号注入 HKDF 盐 | 9.0.1 物理 U 盘 / 移动硬盘锁死容器 |

## 🔍 协议结构详解

### 1. 物理硬件锁容器协议 (`MAGIC_HW_V1`)
当开启物理硬件锁绑定时，输出文件会在最外层写入此容器包装头，内部无损包裹原本的协议流：
```
[ 5 字节: b"SAHW\x01" ]
[ 1 字节: 序列号长度 N (如 8) ]
[ N 字节: UTF-8 设备物理卷序列号 (如 "1A2B3C4D") ]
[ 后续流: 完整的内部协议流 (如 V3, V4, ChaCha, SFK 或 ECC) ]
```

### 2. V4 极速协议流 (`MAGIC_V4`)
针对大批量文件加密优化，在母盐派生主密钥后，对每个文件通过 HKDF-SHA256 快速派生独立文件密钥：
```
[ 5 字节: b"SAES\x05" ]
[ 16 字节: Master Salt (批次母盐) ]
[ 16 字节: File Salt (文件独立盐) ]
[ 8 字节: Nonce File (基础随机数) ]
[ 2 字节: Big-Endian 元数据长度 L ]
[ L 字节: AES-GCM 加密元数据 (8字节原文件大小 + 原始文件名) ]
[ 分块流: 4 字节块密文长度 + 加密块密文 (Nonce = Nonce_File + 4字节块索引) ]
```

### 3. V3 经典高抗爆破协议流 (`MAGIC_V3`)
```
[ 5 字节: b"SAES\x04" ]
[ 16 字节: Salt ]
[ 4 字节: 0x00 保留填充位 ]
[ 4 字节: Nonce ]
[ 2 字节: Big-Endian 元数据长度 L ]
[ L 字节: AES-GCM 加密元数据 ]
[ 分块流: 4 字节块密文长度 + 加密块密文 (Nonce = Nonce + 8字节块索引) ]
```

## 🔒 向后兼容性保障机制
Core Vault 9.0.1 解密引擎采用流式嗅探机制：
1. 先读取前 5 字节魔数；
2. 若为 `SAHW\x01`，则解包硬件锁并提取序列号，实时核验物理硬件插入状态；核验通过后指针移向内部真实魔数；
3. 若非 `SAHW\x01`，则按原生魔数分发至对应解密器（`_dec_v4`, `_dec_v3`, `_dec_v2`, `_dec_v1`, `_dec_sfk`, `_dec_ecc`, `_dec_chacha`）；
4. 若无魔数且勾选了“兼容遗留 V0 格式”，则自动进入 PBKDF2-V0 解密器。
